# SCUT CampusNet Client

华南理工大学校园网 Dr.COM 客户端的 Ubuntu 22.04 兼容修复版本，保留原图形界面和认证协议。

**首次运行一次 `privillege.sh`，之后包括重启后，直接双击 `DrClientLinux`。**

## 适用环境

| 项目 | 要求 |
| --- | --- |
| 系统 | Ubuntu 22.04，amd64 / x86_64 |
| 桌面 | 可用的 X11 显示；Wayland 会话需要 XWayland，尚未实测 |
| 网络 | 已连接校园网的有线网卡；账号和服务器须支持随包提供的 Dr.COM 客户端 |
| 首次配置 | 本机管理员权限 |
| 存放位置 | 用户可写、允许执行程序和 SetUID 的本地目录，例如主目录 |

该发布包包含 64 位原生启动入口、原 Qt 4 图形程序和静态链接的 32 位认证后台。使用预编译文件无需自行编译，也无需单独安装 Qt 4。

## 快速开始

### 1. 获取完整客户端

```bash
git clone https://github.com/Anchirit/SCUT-CampusNet-Client.git
cd SCUT-CampusNet-Client
```

也可以下载仓库 ZIP 并完整解压。请保留整个目录，不能只复制 `DrClientLinux`。

### 2. 首次配置

先退出其他已打开的 Dr.COM 客户端，再在本目录的终端执行：

```bash
sh privillege.sh
```

按提示输入 **Ubuntu 本机管理员密码**。脚本会：

1. 检查程序版本和必要运行库，按需安装缺失的 Ubuntu 运行库。
2. 将认证后台配置为 `root:root` 所有，权限设为 `4755`，沿用原客户端所需的 SetUID 工作方式。
3. 检查挂载选项、网卡信息和程序完整性。
4. 实际启动后台，检查认证类型、网卡列表、版本查询，并确认初始化后持续存活。
5. 结束测试后台；全部检查通过后输出“配置完成”。

### 3. 日常使用

在文件管理器中双击 **`DrClientLinux`**，选择校园网网卡，输入校园网账号和密码，然后点击登录。也可以在终端执行：

```bash
./DrClientLinux
```

- 正常重启后直接打开客户端，无需再次运行配置脚本。
- 不需要用 `sudo` 启动图形界面。
- 重复双击会尝试激活已打开的窗口，避免重复启动。
- 克隆、重新解压或复制到其他电脑后，如果文件所有者或 SetUID 权限丢失，需要重新执行一次 `privillege.sh`。

## 选择哪张网卡

有线校园网应选择实际插网线的 **Ethernet 网卡**。Ubuntu 常见名称为 `enp…`、`eno…`、`ens…` 或 `eth…`；Wi-Fi 网卡常见名称为 `wlp…`。

```bash
nmcli device status
ip -br address
```

例如，如果网线连接在 `enp8s0`，就在客户端选择 `enp8s0`。这个名称只是示例，其他电脑可能不同。不要选择 `tailscale0`、`docker0`、`lo` 等虚拟或回环接口。默认路由可能走 Wi-Fi，不能仅据此判断应该选择哪张有线认证网卡。

## 修复了什么

### 认证后台启动崩溃

原后台 `linux_get_device_network_info()` 遍历网卡地址时会直接解引用空地址指针。实测系统中出现此类记录时，后台以 `SIGSEGV` 退出，界面无法获取认证状态。

本版本为地址和子网掩码增加空指针检查，跳过无效地址记录。补丁只替换原程序中一段 54 字节的机器码，不改写认证协议、账号密码处理或正常登录/退出流程。

### 网卡信息获取

`hostinfo.sh` 在 Linux 上优先使用 Ubuntu 自带的 `ip` 命令，并保留后台需要的文本输出格式。不再依赖本机可能未安装的 `/sbin/ifconfig`，能够处理当前常见网卡名称。

### 启动与权限

- 首次配置改用 `sudo` 或桌面管理员验证，适配 Ubuntu 的权限管理方式。
- `DrClientLinux` 是原生 ELF 可执行入口，双击即可执行；它会自动进入程序目录。
- 启动时清理可能干扰 Qt 4 的库和插件环境变量，使用内置 Qt 4 的栅格绘图。
- 原 Qt 图形程序保存在 `DrClientLinux.qt4`，文件内容与原版一致。

## 自检与常见问题

### 检查运行环境

```bash
./DrClientLinux --check
```

检查文件完整性、架构、所有者及权限、挂载选项、共享库和网卡信息。此命令不会发送账号密码或发起校园网登录；完整的后台通信测试在首次配置时执行。

### 提示先运行 `privillege.sh`

通常是尚未配置，或复制、解压后丢失了后台的 root 所有者/SetUID 权限。在当前目录重新执行 `sh privillege.sh`。

### 提示 2080 或 2081 端口被占用

退出其他 Dr.COM 客户端和后台，再重新运行配置。不要同时启动不同目录中的新旧版本。

### 提示文件系统不允许执行或 SetUID

把完整目录移动到主目录等允许执行和 SetUID 的本地文件系统，再运行首次配置。某些移动硬盘、共享目录或挂载选项为 `noexec` / `nosuid` 的目录不能直接使用。

### 找不到图形显示

请从本机 Ubuntu 图形桌面启动。无图形显示的 SSH 会话无法直接显示登录窗口。X11 已实测，Wayland/XWayland 尚未实测。

### 界面正常，但认证失败

先核对网卡、网线、校园网账号及服务器返回的错误。**客户端正常启动与服务器认证成功是两项独立结果**，自检通过不代表账号已成功登录。

### 日志出现 `No such slot Drcomauthsvr::getReturn()`

这是原 Qt 程序已有的日志，本版本未改写其 Qt 元对象；它不是已定位的网卡空指针崩溃点。应结合后台通信自检和实际认证结果判断运行状态。

## 目录结构

| 文件或目录 | 用途 |
| --- | --- |
| `DrClientLinux` | 日常双击使用的原生启动入口 |
| `DrClientLinux.qt4` | 保持原内容的 Qt 图形程序 |
| `drcomauthsvr` | 修复后的认证后台 |
| `DrClientLinux.rcc`、`translator/` | 原界面资源及翻译 |
| `*.drsc` | 随客户端提供的原认证配置及规则数据 |
| `privillege.sh`、`change.sh` | 首次配置与后台自检 |
| `hostinfo.sh` | 网卡及系统信息获取 |
| `compat/` | 原生入口源码、补丁源码、版本检查及构建脚本 |
| `diagnostics/` | 环境检查和本地通信自检工具 |
| `originals/` | 未修复的原程序及脚本备份 |

## 重新构建

日常使用不需要此步骤。修改兼容代码后，可在 Ubuntu 22.04 amd64 上执行：

```bash
sudo apt-get install gcc binutils libx11-dev python3
sh compat/build.sh
sh privillege.sh
```

后台补丁工具会核对原文件 SHA-256，遇到其他版本会停止，不会盲目覆盖。重新构建后应再次执行首次配置，确认权限和后台运行正常。

- 登录窗口正常显示，能够与后台通信。
- 从其他工作目录启动、环境检查及重复启动处理通过。

尚未据此宣称所有 Linux 发行版、所有桌面或所有校园网账号均可认证成功；实际认证结果取决于学校服务器、网络环境和账号。

运行日志、账号配置、按账号生成的本地数据库和 Python 缓存均不纳入版本控制。原 Dr.COM 二进制及资源保留其原权利归属，本仓库提供兼容性修复，不代表厂商官方版本。
